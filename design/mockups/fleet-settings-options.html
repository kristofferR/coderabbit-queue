The job: change a default that every repo inherits, while seeing how many repos would move and what it costs. There are roughly 25 settings across six groups — enough that how they're organised is the whole design question.

A

Long page, grouped sections

Every group stacked in one scroll, each with its own save. What we have today.

everything findable by scrolling long
Good Ctrl-F finds anything, and related settings sit next to each other so you can see how pacing and quota interact.
Costly Long enough that the bottom groups are rarely seen, and per-group saves scattered down the page make it unclear what's still unsaved.

One group per tab. Each screen is short, with a single save and a dirty marker on the tabs that have unsaved edits.

C

Section nav beside the content

A sticky list of groups on the left, content on the right — the classic settings app. One save bar for the whole page.

orientation keptone save
Good You always know where you are and what else exists; scrolling and jumping both work. A single save bar can total up every pending change across groups.
Costly Spends horizontal space on navigation, and one global save makes a mixed batch (reviewers + pacing) harder to describe in one impact preview.

D

Search every setting

One flat searchable list of all settings with their values, scope and override count — like an editor's settings pane.

fastest if you know the name no structure to learn
Good Unbeatable for “where do I change the min interval?” — type “interval”. Every setting also shows its env-var name, so the docs, the CLI and the UI line up.
Costly Terrible for discovery: a flat list teaches nothing about how pacing, quota and the fire slot relate, which is exactly what a newcomer needs.

Notes on these options
  • The override count is the thing worth protecting in all four — it's what stops a fleet default from being changed blind.
  • C and D combine well: section nav for browsing, a search box that jumps straight to a setting.
  • Only B and C can offer a single "review & save" step; A's per-group saves are simpler to reason about but let unsaved changes hide off-screen.
