The job: answer “is anything stuck, and does it need me?” in about a second — while the quota is blocked, one review is running, four PRs wait for different reasons, one is held, a fix session is working, and one host is broken. Same moment in all four.

A

One table, every PR

No sections. Every pull request crq knows about is a row, with its state and reason as columns you can sort and filter.

maximum densitysortable flattens meaning
Good Everything on one screen with no scrolling between sections, and you can re-sort to ask your own questions — by age, by host, by why-it's-waiting. Scales best as the fleet grows.
Costly “In flight”, “queued” and “held” become just values in a column, so the shape of the queue is something you read rather than see. The one broken host has to fight for attention.

B

Three lanes

The screen is split the way the system actually works: metered review, free co-review, and autofix — each with its own gate and its own work.

teaches the model quota block stays locala PR can span lanes
Good Makes the most misread fact structural: the quota block sits on one column while the other two keep moving. Each lane can state its own gate once instead of repeating it per row.
Costly A PR being reviewed and fixed appears twice, which needs care to not read as duplication — and three columns give each lane less room than one full-width list.

C

Only what needs you

One sentence answers the question, then a short list of things a person must decide. Everything running normally is folded into a line.

calmestglanceable from afar hides the queue
Good Most visits end in “nothing to do” — this makes that the answer in one line instead of five tables you have to scan to conclude the same thing.
Costly When you do want to watch the queue move, you have to expand it. And the page has to judge what counts as “needs you”, which is a rule that can be wrong.

D

The feed is the page

A running stream of what the queue is doing, newest first, with current state as a thin strip on top.

feels aliveexplains itself weak as a status board
Good You can see the machine working, which is reassuring for something that acts on your repos unattended — and cause and effect sit next to each other (quota hit → everything queued).
Costly “What's waiting right now?” means reconstructing it from events. The feed is also only live since the server started, so it can't be the whole truth after a restart.

Notes on these options
  • These answer different questions: A “what's the state of everything”, B “how does this system work”, C “does anything need me”, D “what has it been doing”.
  • They combine well in pairs — C as the top of the page with A beneath it is close to a status page that is calm by default and complete on demand; B's lane headers could group A's table instead of splitting it.
  • All four keep the honest bits: only the front of the queue gets a time, the quota block is named as CodeRabbit's rather than the fleet's, and the feed is labelled as live-only.
