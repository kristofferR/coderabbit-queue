Create the queue’s home

one private repo holds the shared state Do this first

Every host reads and writes one small state file, kept in a git ref inside a private repo of your own. crq init creates it, along with the calibration PR that teaches crq how much review quota you have left, and the Markdown dashboard issue.

crq initcopy
creates kristofferR/crq-home (private) ref crq-state-v3 the shared state issue #12 the Markdown dashboard PR #3 quota calibration
Nothing is written to your other repositories by this step. crq only ever comments on a pull request when a review is actually requested.

Enroll a repository

and decide what happens to its open PRs Then

Enrolling asks one question worth thinking about: should crq start with new pull requests only, or work through the ones already open? The second option can spend a lot of review quota at once, so it tells you the cost before you agree to it.

Optional: let crq fix findings too

autofix, on the machines you choose Optional

With an agent installed, crq can work through findings on its own and push the fixes. It’s off until you install the service on a host, and can be turned off per repository at any time.

Mockup notes
  • The true first run: no state, nothing enrolled. Nav for the data pages is inert with a reason, rather than leading to empty screens.
  • One step is live at a time; later steps stay visible but dimmed so the whole path is legible up front. Step 4’s button is explicitly locked with the reason.
  • Plain language over vocabulary here — “fire slot”, “rounds” and “convergence” never appear on a screen someone sees before they’ve enrolled anything.
  • Two honesty beats: step 2 promises nothing is written to your other repos, and step 4 warns that enrolling a backlog costs quota — the same contract the adder enforces.
